## 2. Module Architecture

### 2.1 Entry / Bootstrap
- **Files:** `src/main.cpp`, `src/main.hpp`, `src/Cheat.hpp`, `src/app/init.hpp`
- **What it does:** Decides EXE vs DLL entry, shows F1 activation prompt, creates the overlay, starts the deferred game-context boot, and runs the present loop.
- **Depends on:** App/overlay, ring-0 bridge, game cache, SDK, menu.
- **Depends on it:** nothing upstream; this is the root.
- **Entry points:** `WinMain` (non-DLL) or `DllMain` → `DeferredEntryProc` → `entry_sequence()`.
- **Public interface:** `g_coreReady`, `global::bStopExecution`, `entry_sequence()`, `RenderLoopIteration()`.

### 2.2 App / Overlay Layer
- **Files:** `src/app/AppWindow.hpp`, `src/app/Renderer.hpp`, `src/app/RenderDevice.hpp`, `src/app/arc_ui_render.cpp`
- **What it does:** Creates a game-owned, layered, click-through overlay `HWND`, syncs its size/position to the game, and presents ImGui/DX9 frames.
- **Depends on:** `dwmapi`, `imgui_impl_*`, `main.hpp` fonts, `menu`.
- **Depends on it:** `main.cpp` calls `AppWindow::Create/SyncToGame/GetHandle` and `GfxPipe::*`.
- **Entry points:** `AppWindow::Create()`, `GfxPipe::Initialize()`, `GfxPipe::BeginFrame/EndFrame()`, `ui::Render()`.
- **Public interface:** `AppWindow::handle`, `AppWindow::SetInteractive()`, `AppWindow::SetStreamProof()`, `GfxPipe::DrawMenu()`.

### 2.3 Ring-0 Memory Bridge
- **Files:** `src/memory/driver_memory.cpp`, `src/memory/driver_memory.hpp`, `src/memory/driver_types.hpp`, `src/memory/interface/ctx.hpp`
- **What it does:** Talks to a kernel driver through two channels: (1) hijacked `NtQueryAuxiliaryCounterFrequency` / `NtConvertBetweenAuxiliaryCounterAndPerformanceCounter` used as an IOCTL dispatch, and (2) a shared-memory ring mapped from a named section.
- **Depends on:** `driver_types.hpp`, `ntdll`, `winternl`.
- **Depends on it:** everything that reads/writes game memory (`ctx`, `SDK.hpp`, `CacheTypes.hpp`, `Loop.hpp`).
- **Entry points:** `c_memory::try_connect()`, `c_memory::attach()`, `c_memory::read()`, `c_memory::write()`.
- **Public interface:** `mem_ctx::read<T>/write<T>`, `read_physical`, `write_physical`, `resolve_cr3_aggressive`.

### 2.4 Game SDK / Memory Model
- **Files:** `src/sdk/SDK.hpp`, `src/sdk/Offsets.hpp`, `src/sdk/Decryptions.hpp`, `src/sdk/Steam.hpp`, `src/sdk/Xbox.hpp`, `src/sdk/Math.hpp`, `src/sdk/Platform.hpp`
- **What it does:** Models UE5 objects as thin pointer wrappers, resolves names via encrypted FName/GObjects, decrypts UObject slots and bone arrays, and provides W2S.
- **Depends on:** ring-0 bridge (`ctx`), Unicorn emulator (`Unicorn.hpp`), `Math.hpp`.
- **Depends on it:** caches and feature loop.
- **Entry points:** `InitializeViewPort()` in `CacheTypes.hpp`, `FName` resolution, `GetObjectFromGObjects`, `WorldToScreen`.
- **Public interface:** `Offsets::Get()`, `NameResolver::*`, `Platform::Steam/Xbox::*`, `ViewContext::Project`.

### 2.5 Cache / World Model
- **Files:** `src/game/WorldCache.hpp`, `src/game/SlowCache.hpp`, `src/game/EntityCache.hpp`, `src/game/CacheTypes.hpp`
- **What it does:** Maintains a multi-layer cache: `EntityCache` (player list + pointers), `SlowCache` (vitals/bones/world state), `WorldCache` (static/dynamic world actors + merged render buffer). Four background threads run the scanners/updaters.
- **Depends on:** SDK, ring-0 bridge, settings.
- **Depends on it:** `Loop.hpp` consumes the merged `PlayerBuffer`.
- **Entry points:** `NT::Store::SpawnWorkers()`, `FrameSync::Tick()`, `FrameDispatch()`.
- **Public interface:** `NT::Store::Entity`, `NT::Store::Scene`, `NT::Store::AsyncPlayer`, `NT::Store::AsyncWorld`, `NT::Store::BoneSyncer`, `AcquirePlayerBuffer()`.

### 2.6 Feature Loop
- **Files:** `src/game/Loop.hpp`
- **What it does:** Per-frame cheat dispatch: reads the merged cache, runs aimbot, draws ESP/radar/arrows, and writes zoom/view-mode/flashlight.
- **Depends on:** cache layer, SDK, draws, settings.
- **Depends on it:** `main.cpp` calls it from `RenderLoopIteration()`.
- **Entry points:** `FrameDispatch()`, `LaunchFrameSyncWorker()`.
- **Public interface:** `FrameDispatch()` is the only external call.

### 2.7 Menu / Config
- **Files:** `src/menu/*`, `src/settings/*`
- **What it does:** Custom object-tree UI rendered onto ImGui draw lists; widgets bind directly to inline global settings; configs saved/loaded as XOR-encrypted `.dat` files.
- **Depends on:** custom framework, `Settings.hpp`, `AppWindow`.
- **Depends on it:** feature loop reads the globals.
- **Entry points:** `Menu::Init()`, `Menu::Tick()`.
- **Public interface:** `Menu::window`, `SyncFromSettings()`, `SyncToSettings()`, `cfg_save()`, `cfg_load()`.

### 2.8 Obfuscation / Stealth
- **Files:** `ext/dgb/Spoof.h`, `ext/dgb/lazy.hpp`, `ext/dgb/skStr.h`, `Unicorn.hpp`, `src/menu/string_encryption.hpp`

### 3.4 Ring-0 component communication
See Section 4 for structs/codes. At runtime:
1. `ctx->initialize_handle()` → `c_memory::try_connect()` → `resolve_transport()` finds `NtQueryAuxiliaryCounterFrequency` or `NtConvertBetweenAuxiliaryCounterAndPerformanceCounter`.
2. `dispatch()` sends a `c_request` through that NT function with the request pointer.
3. If `open_ring()` has been called, a named `FILE_MAPPING` shared region is used instead; `ring_submit()` writes the request, spins on `rsp_seq`, and reads the result.

## 6. Address Management

### 6.1 Where addresses are stored

### 6.2 How addresses get resolved
- **Struct offsets:** hardcoded `constexpr` only; no pattern scanning or signature scanning at runtime.
- **Viewport / UWorld:** `InitializeViewPort()` in `src/game/CacheTypes.hpp` scans decrypted `GObjects` indices `75000..95000` for `EmbarkCommonGameViewportClient`.

## 7. Runtime Protection Surface

### 7.1 Mitigations against runtime detection
- **Return-address spoofing:** `SPOOF_FUNC` from `ext/dgb/Spoof.h` zeros the stack return address inside function bodies. Used across `main.cpp`, `Loop.hpp`, `WorldCache.hpp`, `EntityCache.hpp`, `SlowCache.hpp`, `Textures.h`.
- **Lazy API import:** `LI_FN` PEB walk used in `main.cpp` and `debug.h::findProcess()`.
- **String encryption:** `skCrypt`/`XORSTR`/`SK` in core, `X()`/`xs()` in menu. Inconsistent and partly disabled: `STABLE` is not defined in the project, so menu `X()` strings are plaintext.
- **Unicorn-based vtable emulation:** avoids calling game decrypt stubs in-process.
- **Driver transport obfuscation:** hijacks `NtQueryAuxiliaryCounterFrequency` / `NtConvertBetweenAuxiliaryCounterAndPerformanceCounter` as the IOCTL dispatch channel.
- **Shared-memory ring:** named section with magic/version/nonce; falls back if the syscall hook is unavailable.
- **Overlay stealth:** benign class name `Static.{pid}`, empty title, `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`, no `WS_EX_TOPMOST`, `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`.
- **HWID-derived paths:** config saved under `%LocalAppData%\Microsoft\CLR\{MachineGuid_FNV}.dat`; icon cache under `C:\ProgramData\pc{hash}.bin`.
- **EAC settings patch:** on `PioneerGame-d.exe`, rewrites `EasyAntiCheat\Settings.json` to `PioneerGame-e.exe` and terminates the game.

### 7.2 Hardware identifier handling
- Read from `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`.
- FNV-1a hashed to derive config and icon-cache filenames.
- Used only for path generation, not for auth.

### 7.3 Stealth techniques
- Manual PEB/module walk for `get_module_base()` in `driver_memory.cpp`.
- `WDA_EXCLUDEFROMCAPTURE` for screen-capture exclusion.
- Window owned by the game HWND so it follows z-order without `TOPMOST`.
- Overlay click-through unless menu is open (`SetInteractive`).

### 7.4 Timing / behavior patterns that could be fingerprinted
- **Very regular scheduler:** fast cache thread `Sleep(8)` (~125 Hz), async updater `Sleep(250)`, scene scanner `Sleep(2000)`, FrameSync `Sleep(25)`.
- **Overlay present thread** sets `THREAD_PRIORITY_HIGHEST` and paces to DWM refresh via `DwmGetCompositionTimingInfo`.
- **Always-on debug console** in `WinMain` builds (`AllocConsole()` + `SetConsoleTitleA("Debug Console")`), which is a loud artifact.
- **Plaintext diagnostic strings** in `std::cout`, `std::fprintf(stderr, "[drv] ...")`, and scan messages.
- **Static window class name pattern** `Static.{pid ^ 0xA5A5A5A5}` is still deterministic.
- **Repeated process enumeration** via `CreateToolhelp32Snapshot` at boot and in `FindGamePid`.

## 9. Risk Surface

### 1. Stale offsets
Most struct offsets are hardcoded `constexpr` with no runtime validation. The most fragile ones:
- `0x0` placeholders: `UWorld_NetDriver` (causes `UWorld::GetNetDriverName()` to read offset 0), `UPlayerController_NetConnection`, etc.
- `Arc_HGS_BaseGroup` / `Arc_ActorHealthComponent_MaxHealth` differences between Steam and Xbox look suspicious.
- `Bones` enum collision (`weapon_buffer`/`index_01_r`).
- UE5 updates frequently move `ULocalPlayer`, `UPlayerController`, `UPawn`, and `USkeletalMeshComponent` fields.

### 2. Detectable patterns
- `WinMain` always calls `AllocConsole()` with title `"Debug Console"` — trivial to fingerprint.
- `std::cout << "[Boot] ..."` and `[drv]` stderr logs leak plaintext.
- `SPOOF_FUNC` is applied widely but the macro itself is a static pattern; the zeroed return-address behavior is also detectable.
- Window class name `Static.{pid ^ 0xA5A5A5A5}` is deterministic.
- `WDA_EXCLUDEFROMCAPTURE` is an explicit flag.

### 3. Fragile driver transport
- The entire memory layer relies on a hijacked exported NT function being hooked by an external driver. If the driver is not loaded or the hook is removed, the cheat silently fails after retries.
- The shared-memory ring fallback requires a pre-existing named section with a matching 32-byte nonce.
- `dispatch_inner` swallows access violations with a fixed `0xC0000005` status and no retry/backoff logic beyond the caller loops.

### 4. Race conditions
- `g_LockedArcEntity` / `g_ArcLockTime` are read/written in `ExecuteAssistARC` on the render thread with no synchronization against cache workers.
- `m_playerNameCache` in `EntityCache.hpp` has no mutex.
- `m_visibilityCache` in `WorldCache.hpp` has no mutex.
- `combatModeActive` is toggled on the render thread but not atomic.
- Full-map copies every 8 ms from async caches can produce torn snapshots.

### 5. High-allocation / performance fragility
- `AsyncPlayer->GetSnapshot()` and `AsyncWorld->GetSnapshot()` return by-value copies of entire `unordered_map`s on every fast tick.
- `IndexStaticScene()` can scan up to 20k actors per level; `GetObjectNameA` per actor is expensive.
- `VTableEmulator` creates a new Unicorn engine per GObjects call; failure here breaks object resolution entirely.

## 10. Recommended Next Actions

### 1. Remove dead code and unify encryption
- Delete `ext/imgui/gui/gui.cpp` (or stop compiling it), `ext/dgb/Encrypt.h`, `ext/dgb/xor.hpp`, `src/memory/crash_log.h`, `src/memory/utils.h`.
- Pick one string-encryption system and apply it consistently; remove `std::cout`/`stderr` debug strings from release.

### 2. Gate debug console output
- Move `AllocConsole()` and all `std::cout`/`fprintf(stderr)` behind a `DEBUG`/`STABLE` preprocessor flag that is off in release.
- Remove the hardcoded `"Debug Console"` title.

### 3. Fix ARC aimbot wiring
- Make `ArcAimCfg.fov`, `ArcAimCfg.maxHz`, and `ArcAimCfg.weakspotKey` actually used by `ExecuteAssistARC`, or remove them from settings and menu.
- Add a dedicated ARC aim keybind widget if that is the intended UX.

### 4. Stabilize the memory transport
- Add proper fallback behavior when the driver/ring is absent (e.g., exit cleanly instead of spinning).
- Add status returns through `ctx.hpp` so callers can detect read failures and stop writing.
- Validate `m_transport_fn` and `m_ring_ready` before every batch, not just the first attach.

### 5. Add runtime offset validation
- Add a health-check function that reads known stable values (PE header, `UWorld` signature, `GObjects` count) and reports which offset group is failing.
- Replace the `0x0` placeholders with real offsets or remove the functions that use them.
- Consider a small signature scan for at least the viewport client and local player controller to survive minor UE5 patches.
